# 整任务裁判输入图片包

在任务的“③ 结果”区域点击“导出裁判输入图片 ZIP（整任务）”。历史任务加载后同样可下载。导出针对所选任务的全部 Case，不受当前结果页码、分数或理由筛选影响；原“导出视觉证据 ZIP”继续提供预处理文件及原图。

## 包含哪些图片

- 录屏 Case：保存并导出发送时经缩放、JPEG 编码的采样帧字节，不在导出时重新抽帧或重新编码。
- 长截图 Case：未切分时导出实际使用的原图；切分时只导出发送的切片序列，不额外附带完整原图。各产品截图齐全时优先截图，否则沿用统一录屏回退规则。
- 图文题：包含模型实际使用的提问图片版本，不额外复制未发送的提问原图。
- 多轮题：每个目标轮次独立成一个 Case 目录，包含该请求携带的共享题图、各产品历史图片和当前回答图片。历史图片在不同请求中重复发送时会出现在各自 Case 的包内序列中。
- 失败、预算拦截、尚未评测及暂停未完成的 Case 不导出图片；结构化结果最终解析失败也属于失败。

录屏和长截图均在实际请求组装后冻结图片字节。只有评估成功才将请求记录绑定到该条结果；补跑、恢复、更新和历史回载沿用结果中的记录，不从可变输入路径推断。更新版本前未冻结实际请求的旧录屏 Case 不能精确重建，会在清单中标记 `request_not_recorded`，需重新评估。旧长截图审计已冻结且确认模型响应成功的记录可沿用。

## ZIP 结构与完整性

图片放在 `case_0001/image_0001.jpg`（或 PNG/WebP）这样的路径下，Case 编号按测试集输入顺序，图片编号按该 Case 请求中的图片顺序。`manifest.json` 包含任务名、总 Case 数、导出数、跳过原因、产品序号、来源轮次、历史/当前角色、切片/帧序号、原引用及 SHA256。包内另有 `README.txt`。

导出校验冻结文件的授权路径、格式和 SHA256；成功请求的证据文件缺失或变化时拒绝提供不完整的包，不以其他原图代替。没有可导出的成功请求时返回明确提示。保存目录沿用 `runs/screenshot_evidence/` 的内容哈希存储，与输入文件变化隔离；保存历史任务时应一并保留该目录。

服务接口：`GET /api/eval/{task_id}/export?format=model_input_evidence`。打包在线程中写到磁盘，下载使用文件响应，下载结束清理临时 ZIP；整个 ZIP 不先读入服务端内存。

## 验证

`tests/test_model_input_evidence.py` 验证双/三产品混合批次、长截图优先与录屏回退、请求 JPEG 字节、图文题、多轮历史顺序、失败/解析失败/预算拦截排除、结果与历史回载绑定、源文件替换隔离、缺失与变化检查、旧任务兼容及下载清理。`tests/test_model_input_evidence_ui.cjs` 验证任务切换保护、完整任务下载和筛选隔离。测试使用模拟视频抽帧和模拟裁判响应，实际运行图片编码、切分、冻结、打包和 HTTP 下载代码。
