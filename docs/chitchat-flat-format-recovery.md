# 闲聊七维输出的受控本地格式恢复

闲聊七维评估使用 `chitchat_evidence_first_flat@1.1` 协议。裁判已给出完整判断，但理由中的双引号没有转义，或评分键采用已知的字段片段顺序时，原先会因格式不符合严格 JSON 合同而失败。本次为这两类确定的格式问题增加本地恢复，不再请求模型补写结果。

## 恢复边界

评估先执行原有的严格解析。严格解析失败后，仅闲聊七维路径可以尝试以下恢复：

- 对理由字符串中可以确定边界的内部双引号补充 JSON 转义，保留理由文本的内容。
- 将七个既定维度、当前活动产品对应的白名单评分键别名映射为 `answerN_<dimension>_score`。例如 `style_answer1_score` 对应 `answer1_style_score`。这只调整字段命名，保留产品编号和模型原分数。

恢复候选仍须通过完整的严格字段和类型校验：双产品恰好具有 21 个输出字段，三产品恰好具有 28 个字段；理由必须为非空字符串，分数必须是允许范围内的严格整数或合同允许的空分。响应体验、安全稳定仍只允许整数 1 或 5。合法 JSON 中字段的排列顺序本来就不影响评分。

重复键、别名与规范键碰撞、字段缺失、未知字段、截断输出、无法确定的引号边界、错误的分数类型或范围均不能通过本地恢复补全。程序不生成分数或理由，不将字符串、布尔值或浮点数转换为整数分，不改动其他协议的解析策略。其他协议和原有严格 schema 保持原行为。
