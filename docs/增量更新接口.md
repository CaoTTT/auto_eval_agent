# 增量更新接口

向已有评测任务批量提交题目的外部 API,共两个端点:

| 端点 | 用途 |
|---|---|
| `POST /api/eval/items` | 按 task_id 提交一批 items,后台评测(非流式,立即返回) |
| `GET /api/eval/item/result` | 轮询单条 item 的当前结果 |

## 核心规则

1. **upsert 语义**:`task_id` 不存在时直接用调用方传入的 id 新建任务;已存在时按 item `id` 匹配 —— 命中则**原位替换**该题(index 不变)并重评,未命中**追加到任务末尾**评测。
2. **批次独立**:每次调用的全部 items 作为**一个多轮 session、按列表顺序串行**评测(第 N 轮评完生成的总结会注入第 N+1 轮的 context)。批次之间**完全并行、互不协调**;同一 id 被多个批次同时重评时,**后完成的结果覆盖先完成的**。
3. **非流式**:提交接口立即返回合并摘要,不推 SSE;结果通过单条查询接口轮询获取,"有什么结果拿什么结果"。

## POST /api/eval/items

### 请求

`Content-Type: application/json`

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `task_id` | string | 是 | 任务标识。**允许所有字符**(含中文/符号),非空、≤128 字符;不存在则新建 |
| `mode` | string | 新建必填 | `rich_content`(垂域视觉评测)或 `compare`(垂域视觉对比)。更新已有任务可省略(沿用任务 mode);与任务不一致返回 422 |
| `items` | list[object] | 是 | 本次批次题目,不可为空。**每条必须带非空字符串 `id`,且批内唯一** |
| `options` | object | 否 | 本次批次运行参数(见下),缺省沿用任务原配置;**仅本次生效,不回写任务配置** |
| `dataset_name` | string | 否 | 数据集名,仅新建任务时生效,更新时忽略 |

`options` 可选字段:`judges`(裁判名列表,默认取第一个)、`concurrency`(并发数,默认 4)、`eval_timeout_s`(单题超时秒数,默认 300)、`video_prepare_timeout_s`(抽帧超时秒数,默认 300)。

### item 字段

rich_content 模式:

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | string | 是 | 题目标识,所有字符,≤128 字符,批内唯一;跨批次去重/替换的主键 |
| `query` | string | 是 | 题目/用户问题 |
| `video_path` | string | 是 | 视频路径(相对项目根目录,或经 `OPERATION_VIDEO_ROOTS` 授权的绝对路径) |
| `context` | string | 否 | 背景信息;多轮场景由系统自动追加"历史对话总结" |
| `task_start_time` | number | 否 | 任务起始时间(秒),默认 0 |
| `task_end_time` | number | 否 | 任务结束时间(秒),须大于 start;缺省按默认策略 |
| `answer_text` | string | 否 | 参考答案 |
| `category` | string | 否 | 垂域分类,默认 `default` |

compare 模式:以 `video1` + `video2`(两路视频,均必填)替代 `video_path`,可选 `context1`/`context2`/`answer1`/`answer2`;其余同上。

### 响应

```json
{
  "task_id": "batch-20260820-001",
  "created": true,
  "replaced_ids": [],
  "added_ids": ["q1", "q2"],
  "total_items": 2
}
```

| 字段 | 说明 |
|---|---|
| `task_id` | 任务 id(即传入的 task_id) |
| `created` | 本次调用是否新建了任务 |
| `replaced_ids` | 命中已有 id、被原位替换重评的题目 |
| `added_ids` | 未命中、追加到末尾的新题目 |
| `total_items` | 合并后任务的总题数 |

### 错误码

| 状态码 | 场景 |
|---|---|
| 400 | `items` 为空 |
| 422 | `task_id` 空白或超过 128 字符;某条 item 缺少非空字符串 `id`;批内 `id` 重复;`id` 超长;新建任务未提供 `mode`;`mode` 与任务不一致;compare 模式缺 `video1`/`video2` |

### 示例:首次调用(新建任务)

```bash
curl -X POST http://localhost:8054/api/eval/items \
  -H "Content-Type: application/json" \
  -d '{
    "task_id": "batch-20260820-001",
    "mode": "rich_content",
    "items": [
      {
        "id": "q1",
        "query": "帮我查一下明天北京的天气",
        "context": "用户所在位置信息：北京",
        "video_path": "videos/session1.mp4",
        "task_start_time": 0,
        "task_end_time": 45
      },
      {
        "id": "q2",
        "query": "那后天呢？",
        "video_path": "videos/session1.mp4",
        "task_start_time": 45,
        "task_end_time": 90,
        "answer_text": "北京后天多云转晴，18~26度"
      }
    ],
    "options": { "concurrency": 2 },
    "dataset_name": "天气助手批次1"
  }'
```

q1、q2 作为一个 session 串行评测:q1 的总结会注入 q2 的 context 后再评。

### 示例:再次调用(混合替换与追加)

```bash
curl -X POST http://localhost:8054/api/eval/items \
  -H "Content-Type: application/json" \
  -d '{
    "task_id": "batch-20260820-001",
    "items": [
      { "id": "q2", "query": "那后天呢？顺便提醒我带伞",
        "video_path": "videos/session1_v2.mp4", "task_start_time": 45, "task_end_time": 95 },
      { "id": "q3", "query": "换个城市，上海呢？", "video_path": "videos/session2.mp4" }
    ]
  }'
```

`q2` 原位重评(换视频会自动重新抽帧),`q3` 追加到末尾;`mode`/`options`/`dataset_name` 均可省略。

## GET /api/eval/item/result

### 请求

Query 参数(task_id、item_id 均经 URL 编码,支持任意字符):

| 参数 | 必填 | 说明 |
|---|---|---|
| `task_id` | 是 | 任务 id |
| `item_id` | 是 | 题目 id(只匹配显式带 id 的题;404 表示任务或题目不存在) |

### 响应

```json
{
  "task_id": "batch-20260820-001",
  "item_id": "q2",
  "index": 1,
  "item": { "id": "q2", "query": "那后天呢？", "video_path": "videos/session1.mp4", "...": "..." },
  "result": {
    "query_id": "q2",
    "Query": "那后天呢？",
    "context": "用户所在位置信息：北京",
    "垂域分类": "天气",
    "correctness": "OK",
    "评价的原因": "回答完整覆盖了用户问题",
    "error_type": "",
    "识别结论": "…",
    "评价分析过程": "…",
    "...": "全部列见下方「result 字段与 xlsx 导出列对照」"
  },
  "evaluating": false,
  "status": "done"
}
```

| 字段 | 说明 |
|---|---|
| `index` | 该题在任务中的下标(替换不变、追加续排) |
| `item` | 当前题目定义(可能已被后续批次替换) |
| `result` | **最新已完成**的评测结果,键与 xlsx「逐题结果」导出列同名、值同转换(见下方对照表);**多余字段不返回**;失败时额外附 `error`;从未评过为 `null` |
| `evaluating` | 查询时刻是否有更新批正在评测该题 |
| `status` | 派生状态,见下表 |

### status 与 evaluating

| status | 条件 | result 内容 |
|---|---|---|
| `evaluating` | 有批次正在评测该题(`evaluating: true`) | **旧结果**(上次评测的)或 `null`(从未评过),不是本次进行中的结果 |
| `done` | 无批次在评,且最新结果成功 | 最终结果 |
| `failed` | 无批次在评,且最新结果失败 | 结果的 `error` 字段含失败原因 |
| `pending` | 无批次在评,且从未评测过 | `null` |

要点:

- `evaluating: true` 期间的 `result` 是**旧值**,不要当作最终结论使用;标志一旦回到 `false`,`result` 必然已是新结果(合并与标志清除是原子的,不存在中间窗口)。
- 一次替换重评的时序:

  ```
  POST 更新 q2(原结果 R1)
    ├─ 评测期间查询 → evaluating: true,  result: R1(旧), status: "evaluating"
    └─ 新结果 R2 评完按 index 覆盖落库
        └─ 查询 → evaluating: false, result: R2(新), status: "done"
  ```

### 轮询示例(Python)

```python
import time
import requests

BASE = "http://localhost:8054"

def wait_result(task_id: str, item_id: str, timeout: float = 600) -> dict:
    deadline = time.time() + timeout
    while time.time() < deadline:
        body = requests.get(
            f"{BASE}/api/eval/item/result",
            params={"task_id": task_id, "item_id": item_id},
            timeout=30,
        ).json()
        if body["status"] in ("done", "failed"):
            return body
        time.sleep(5)   # evaluating / pending → 继续等
    raise TimeoutError(f"{item_id} 评测超时")

info = submit(...)  # POST /api/eval/items 的返回
for item_id in info["added_ids"] + info["replaced_ids"]:
    result = wait_result("batch-20260820-001", item_id)
    print(item_id, result["status"])
```

## result 字段与 xlsx 导出列对照

本接口返回的 `result` 与导出接口(`GET /api/eval/{task_id}/export?format=xlsx`,CSV 同列名)的"逐题结果" sheet **共用同一套列定义与转换**:`result` 的键就是下表的 xlsx 列名,值也一致(枚举翻译、列表拼接);除这些列外**只有失败时的 `error`**,其余原始字段一律不返回。导出以 items 为主表左连接 results(index 优先、item_id 兜底),行序 = 任务内题目顺序(替换原位、追加在末尾),失败/待评估条目保留行位、评分列留空。

### rich_content 模式

| 评测原始字段 | xlsx 列 / result 键 | 导出转换 |
|---|---|---|
| `item_id` | query_id | 原样 |
| `query` | Query | 原样 |
| `context` | context | 原样 |
| `category_display` | 垂域分类 | 原样 |
| `answer_text` | answer_text | 原样 |
| `card_presence_label` | 卡片存在情况 | 原样 |
| `card_count` | 卡片数量 | 原样 |
| `card_types` | 卡片种类 | 列表 → 以"；"拼接 |
| `card_contents` | 卡片内容 | 列表 → 以"；"拼接 |
| `superlink_presence_label` | Superlink存在情况 | 原样 |
| `superlink_count` | Superlink数量 | 原样 |
| `superlink_texts` | Superlink文字 | 列表 → 以"；"拼接 |
| `card_suitability` | 卡片是否合适 | `ok`→OK / `nok`→NOK |
| `card_suitability_reason` | 卡片不合适原因 | 原样 |
| `needs_review_label` | 识别是否需要人工复查 | 原样 |
| `review_reason` | 需要复核的原因 | 原样 |
| `problem_solved` | correctness | `ok`→OK / `nok`→NOK / `need_review`→需复查 |
| `problem_solved_reason` | 评价的原因 | 原样 |
| `answer_issues` | error_type | 原样 |
| `rationale` | 识别结论 | 原样 |
| `analysis` | 评价分析过程 | 原样 |

**不再导出、result 也不返回**的字段:`superlink_suitability`(Superlink是否合适)、`superlink_suitability_reason`(Superlink不合适原因)、`answer_coverage`(回答覆盖)、`latency_s`(耗时);其余原始字段(`index`、`turn_summary`、`card_presence`、`superlink_presence`、`needs_review`、`category`、`judge`、`judge_model`、`judge_latency_ms`)同样不返回——`error` 仅失败时附加。缺失列在 result 中为空字符串。原始题目字段与帧路径在"数据集明细" sheet,"数据集序号"= index + 1。

### compare 模式

| 评测原始字段 | xlsx 列 / result 键 | 导出转换 |
|---|---|---|
| `item_id` | query_id | 原样 |
| `query` | 题目 | 原样 |
| `context` | 背景 | 原样 |
| `context1` | 产品1背景 | 原样 |
| `answer1` | 产品1回答 | 原样 |
| `context2` | 产品2背景 | 原样 |
| `answer2` | 产品2回答 | 原样 |
| `relevance` | 相关性 | `answer1`→产品1更优 / `answer2`→产品2更优 / `tie`→平手 |
| `safety` | 安全合规 | 同上 |
| `content_quality` | 内容质量 | 同上 |
| `need_closure` | 需求闭环 | 同上 |
| `personalization` | 个性化一致性 | 同上 |
| `has_conflict` | 内容冲突 | `yes`→有冲突 / `no`→无冲突 / `unclear`→不清楚 |
| `rationale` | 理由 | 原样 |

compare 的 `*_reason`(各维度理由)、`conflict_reason`、`needs_review` 系列字段与 `latency_s`(耗时)**不导出、不返回**;缺失列显示 N/A。裁判调用明细可通过 `GET /api/eval/{task_id}/items/{index}/export?format=judge_calls` 获取完整 JSON。

## 行为细节与边界

- **批次间并行、后写赢**:多个批次(含与 Web UI 全量跑同时)可同时更新一个任务;结果按 index 从后往前查找并整体替换。极端情况下可能出现"新题目定义配旧结果"的短暂窗口,由 `evaluating` 标志暴露,属预期行为。
- **题目定义即时生效,结果完成才覆盖**:POST 时 item 定义立即合并进任务并落快照;结果在各题评测完成后逐条覆盖,期间查询拿旧结果。
- **`options` 不回写**:批次的 `options` 只在本次运行生效,任务快照保留原配置。
- **任务状态**:更新已有任务不改 `status`/`done_total`、不发 start 事件;批(并行批次时为最后一个)结束后向 SSE 订阅者补发一次终态 done/error 事件,避免订阅者干等(2026-08-25 起,详见 问题.md 第七节 R4)。仅当本接口**新建**任务时走完整生命周期(pending → running → done/error)。批被取消/服务中断时任务置 error(「服务中断」)并保留已完成结果。
- **`evaluating` 为内存态**:不进快照,服务重启后丢失(在评的题显示旧结果 + 非 evaluating);该标志只由本接口的更新批维护,Web UI `/api/eval` 全量跑不维护(全量跑期间显示 `pending`)。
- **抽帧缓存**:同一题(index/id 相同)换视频重评会自动重新抽帧,不会复用旧视频的关键帧。
- **快照与导出**:合并后的任务出现在 `/api/history` 列表,可正常使用详情、导出(xlsx/csv/json)等既有接口;任意字符 task_id(含中文)通过文件名短哈希 + 快照内 task_id 字段校验保证互不混淆。

### 内存优化相关的行为变化(2026-08)

- **快照落盘节流**:单题结果落快照改为 debounce(默认 2 秒,环境变量 `AUTO_EVAL_PERSIST_DEBOUNCE_S` 可调,每 20 题强制落一次);批次结束/异常/任务退休前必强制落盘。**语义变化**:服务进程崩溃时最多丢 debounce 窗口内未落盘的结果,正常结束保证盘上完整;`eval_errors.jsonl` 与裁判 trace 仍即时写。轮询接口读内存态,不受节流影响。
- **任务对象退休**:评测批结束后任务对象从内存注册表退休(磁盘快照是唯一真源,下次按 task_id 提交/查询时自动回载);运行中的任务始终驻留。`GET /api/history` 列表改读每快照的 `.meta.json` 摘要侧车,不再全量解析历史快照。
- **删除历史返回 409**:任务运行中(active 批存在)时 `DELETE /api/history/{task_id}` 返回 409 拒绝删除,结束后正常删除(同时清理内存副本与侧车文件)。提交返回的瞬间即视为运行中(提交时同步 pin,2026-08-25 起),不存在「已提交但尚可删除」的窗口。
- **SSE 订阅制**:每个 `/api/eval/{task_id}/stream` 连接独立有界队列(上限 500 事件,满则丢最旧保最新);修复了旧实现多连接互相瓜分事件的问题。连接时的终态回放判定叠加运行计数:更新批运行期间新连接不会立即收到伪 done,需等批结束的终态事件。
