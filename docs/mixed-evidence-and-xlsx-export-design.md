# 混合证据选择与 Excel 原图集中导出

## 需求与规则

同一批数据允许有长截图 Case 和录屏 Case；同一 Case 的全部对比产品必须使用同一种证据层。支持双产品和三产品，提问原图是共享输入，不参与产品证据层选择。

| `evidence_mode` | 所选层字段 | 处理 |
| --- | --- | --- |
| `long_screenshot` | 全部产品的 `screenshotN` 齐全 | 全产品使用长截图与长截图裁判提示词 |
| `video_frames` | 全部产品的 `videoN` 齐全 | 全产品使用录屏采样帧与视频裁判提示词 |
| 未声明 | 全部产品的 `screenshotN` 齐全 | 按 `long_screenshot` 处理 |
| 未声明 | 长截图不完整，全部产品的 `videoN` 齐全 | 回退按 `video_frames` 处理 |
| 任意 | 显式层存在缺失，或未声明时两层都不完整 | 拒绝该 Case |

允许同时提供 `screenshot1/2/3` 和 `video1/2/3`。显式 `evidence_mode` 严格决定实际证据层，即使另一层更完整也不切换；未声明时优先使用完整长截图，否则尝试完整录屏。按各层路径字段是否为非空字符串判断是否齐全，未知声明报错。文件存在性、访问权限、可解码性由页面文件检查和运行前预处理校验。文件损坏或丢失时报告准备失败，不自动切换到另一证据层。

## 导入与执行

- JSON 数组、单对象、JSONL 共用逐条校验。无法统一证据的 Case 从本次导入结果移除，其余 Case 保持输入顺序；原文件不改动。
- `/api/parse` 返回接受数量 `count`、拒绝数量 `rejected_count`、`evidence_counts`，以及带原始条目/行号、Case ID 和缺失字段的 `errors`。
- 页面立即显示接受/拒绝数量、长截图/录屏数量，并展开拒绝原因。全部拒绝时保留原有输入，明确提示本文件未载入。JSON 语法错误无法定位单个 Case 时，按错误条目报告。
- 归一化后的执行输入只保留选中的产品证据路径，完整上传字段保留在 `source_data` 供溯源。
- 手动编辑默认选中长截图，也允许显式切换到录屏；选中的证据层不完整时禁止提交。导入数据未声明 `evidence_mode` 时优先长截图、再回退录屏。页面展示实际采用的证据层、统计及预览；历史只读预览保留任务实际采用的层。
- 直接提交 `/api/eval` 同样按显式证据层归一化并清除旧预处理帧/截图元数据，避免另一证据层的缓存被复用；包含无效 Case 时整次请求返回 422，不创建任务。页面导入会先剔除无效 Case。
- 执行器和实际评测证据清单遵循归一化后的 `evidence_mode`；Excel 原图列独立读取已提供的长截图，包括 `source_data` 中保留的非选中截图。历史数据未声明模式时保留既有评测证据推断兼容。

## Excel 布局

保持首表 `数据集明细`、第二表 `逐题结果` 的顺序。所有原图仅在第二表插入：

- 有提问图片时，在 `题目` 后新增 `输入图片原图`，按原有 WPS `DISPIMG` 单元格图片方式嵌入。
- 测评数据提供长截图时，无论是否作为裁判证据，在各 `产品N回答` 后增加 `产品N原图`，插入对应产品的完整原始长截图。显式录屏 Case 中仅有部分产品提供截图时，也按产品对应列插入；未提供截图的单元格留空。
- 删除 `原始长截图` 和重复嵌图的 `提问图片` 工作表。图片清单/视觉证据清单保留文本路径、哈希等元数据，便于追溯。
- 保留原文件字节、MIME、哈希核验、缺失/变更提示、包内按哈希去重及既有图片显示尺寸；不压缩、不重编码、不以裁判切片代替原图。

减少重复工作表和单元格图片引用。由于旧版已对媒体字节按哈希去重，具体文件体积降幅取决于数据内容，不能保证按原图片数量同比下降。

## 验证

- 覆盖双产品/三产品全部 80 种证据存在组合，验证优先级、回退、拒绝原因和导入/直接提交一致性。
- 同一批任务经过执行器及模拟裁判客户端，验证每条 Case 选中对应提示词，且全部产品采用同一证据层。
- 验证部分拒绝/全部拒绝的前端提示与提交数据，备用证据不会重新进入执行输入。
- 解析生成 XLSX 的工作表、图片关系与媒体字节，验证只有第二表嵌图、列位置正确、原图字节不变，并覆盖缺图、文件变更、双/三产品混合和显式录屏。
