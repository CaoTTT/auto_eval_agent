# 混合证据选择与 Excel 原图集中导出

## 需求与规则

同一批数据允许有长截图 Case 和录屏 Case；同一 Case 的全部对比产品必须使用同一种证据层。支持双产品和三产品，提问原图是共享输入，不参与产品证据层选择。

| 全部产品长截图齐全 | 全部产品录屏齐全 | 处理 |
| --- | --- | --- |
| 是 | 任意 | 全产品使用长截图与长截图裁判提示词 |
| 否 | 是 | 全产品使用录屏采样帧与视频裁判提示词 |
| 否 | 否 | 拒绝该 Case，报告缺少哪些产品的长截图、哪些产品的录屏 |

允许同时提供 `screenshot1/2/3` 和 `video1/2/3`。按路径字段为非空字符串判断是否齐全；已知的 `evidence_mode` 声明不覆盖上述优先级，未知声明仍报错。文件存在性、访问权限、可解码性由页面文件检查和运行前预处理校验。文件损坏或丢失时报告准备失败，不在执行中为个别产品静默切换证据。

## 导入与执行

- JSON 数组、单对象、JSONL 共用逐条校验。无法统一证据的 Case 从本次导入结果移除，其余 Case 保持输入顺序；原文件不改动。
- `/api/parse` 返回接受数量 `count`、拒绝数量 `rejected_count`、`evidence_counts`，以及带原始条目/行号、Case ID 和缺失字段的 `errors`。
- 页面立即显示接受/拒绝数量、长截图/录屏数量，并展开拒绝原因。全部拒绝时保留原有输入，明确提示本文件未载入。JSON 语法错误无法定位单个 Case 时，按错误条目报告。
- 归一化后的执行输入只保留选中的产品证据路径，完整上传字段保留在 `source_data` 供溯源。
- 手动编辑同样依据当前字段自动选择完整证据层；编辑类型下拉只切换正在填写的字段，不覆盖优先级。页面展示实际采用的证据层、统计及预览；缺少统一证据时禁止提交。历史只读预览保留任务实际采用的层。
- 直接提交 `/api/eval` 同样应用优先级并清除旧预处理帧/截图元数据，避免另一证据层的缓存被复用；包含无效 Case 时整次请求返回 422，不创建任务。页面导入会先剔除无效 Case。
- 执行器与导出器优先遵循归一化后的 `evidence_mode`，防止 `source_data` 中保留的非选中截图影响录屏评测或导出。历史数据未声明模式时保留既有推断兼容。

## Excel 布局

保持首表 `数据集明细`、第二表 `逐题结果` 的顺序。所有原图仅在第二表插入：

- 有提问图片时，在 `题目` 后新增 `输入图片原图`，按原有 WPS `DISPIMG` 单元格图片方式嵌入。
- 有长截图证据时，在各 `产品N回答` 后增加 `产品N原图`，插入对应产品实际使用的原始长截图；同表中的录屏 Case 不插入备用长截图。
- 删除 `原始长截图` 和重复嵌图的 `提问图片` 工作表。图片清单/视觉证据清单保留文本路径、哈希等元数据，便于追溯。
- 保留原文件字节、MIME、哈希核验、缺失/变更提示、包内按哈希去重及既有图片显示尺寸；不压缩、不重编码、不以裁判切片代替原图。

减少重复工作表和单元格图片引用。由于旧版已对媒体字节按哈希去重，具体文件体积降幅取决于数据内容，不能保证按原图片数量同比下降。

## 验证

- 覆盖双产品/三产品全部 80 种证据存在组合，验证优先级、回退、拒绝原因和导入/直接提交一致性。
- 同一批任务经过执行器及模拟裁判客户端，验证每条 Case 选中对应提示词，且全部产品采用同一证据层。
- 验证部分拒绝/全部拒绝的前端提示与提交数据，备用证据不会重新进入执行输入。
- 解析生成 XLSX 的工作表、图片关系与媒体字节，验证只有第二表嵌图、列位置正确、原图字节不变，并覆盖缺图、文件变更、双/三产品混合和录屏回退。
