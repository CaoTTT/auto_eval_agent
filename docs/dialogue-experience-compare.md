# 对话体验综合评估接入

新增独立的 `dialogue_experience_compare@1.0` 可选协议，面向同一 Query 下两款或三款手机助手的综合对话体验。任务型、知识型、闲聊型共用上传文件 `executor_main2.py` 中的完整十二项标准和总分判档，最终仅给每产品一个 1—5 整数总分。现有默认协议、已有模板和旧任务冻结修订均不替换。

## 协议与标签

| 项目 | 值 |
| --- | --- |
| 展示标签 | 对话体验对比 \| 标准S1.0 \| Prompt P01 \| Qwen3.8-Flash \| 实验 |
| 版本代号 | EXP-S1.0-P01 |
| standard_id | dialogue_experience_compare |
| standard_version / bundle_revision | 1.0 / 1.0.0 |
| result_schema_version | dialogue-experience-result-1 |
| 唯一统计维度 | overall（综合体验），严格整数1—5 |
| Gate / 维度平均 | 无Gate，不将十二项标准逐项打分或求平均 |

标签沿用“标准名称、S版本、P序号、模型、状态”规范。S1.0表示此平台新协议首版，不重命名上传代码注释中原标准来源的“融合版2.0 / 执行标准2.1”。标签中的模型名称不强制切换任务实际选择的裁判模型；实际模型仍由现有运行配置选择并冻结。

## 输入与证据

复用平台 compare 的导入和预处理，不新增待采集字段，不把未知原始列或 `source_data` 当作可用证据。

| 原平台输入 | 新Prompt用途 |
| --- | --- |
| query / question | 共享用户问题 |
| context1 / context2 / context3 | 各产品背景和测试条件，独立归属 |
| answer1 / answer2 / answer3 | 各产品复制回答，仅作辅助文本 |
| screenshotN / videoN | 沿用现有长截图优先和录屏抽帧规则，附带实际图片消息 |
| query_images | 共享用户题图，不能与产品回答配图混用 |
| session_id / turn_index / target_turn | 沿用原始历史前缀，只评价目标轮 |
| include_prior_knowledge | 原平台先验知识开关，不充当参考答案或检索结果 |

原Prompt中的 `current_time_beijing`、`user_info`、`user_md`、`knowledge`、`resultDataList`、`intent`、`slots`、`intent_explain`、`slot_explain` 缺少正式来源，均明示为空。单轮 `context=[]`，背景另行提供；多轮历史由平台已有的原始用户轨迹与各产品各自回答/截图构建。不从 Query、图片或未知列伪造这些结构化字段，也不因缺少字段自动判失败。

测试绝对时间只采用该产品背景/原始证据明确给出的时间；`evaluation_datetime` 和 `evaluation_run_at` 是评估调用审计时间，录屏起止时间是视频相对秒数，均不能冒充产品实际测试时间。图片由原有安全下载、预处理、切片、预算和 `image_url` 通道发送，文件路径及图片数量不能证明模型看到了图像内容。

多轮沿用 `shared_script`、每轮原始长截图和 `current_turn` 范围校验；本接入不放宽原有录屏/多轮或累计截图限制。当前产品不能借另一产品背景或历史补齐答案；旧轮缺陷仅在当前继续产生影响时评。

## 模型输出

单次裁判请求包含两款或三款产品，模型只返回活动产品的嵌套对象，每对象恰好保留上传Prompt原来的四字段。双产品不输出 `answer3`，也不输出 Gate、各维分数、排名或适用性。

```json
{
  "answer1": {
    "score": 5,
    "reason": "【类型：知识型；目标：完成单位换算；主查：准确性和覆盖；证据状态：充分】回答给出正确结果和要求的换算过程，需求充分满足。",
    "suggestion": "无",
    "domain": "未定义"
  },
  "answer2": {
    "score": 3,
    "reason": "【类型：知识型；目标：完成单位换算；主查：准确性和覆盖；证据状态：充分】结果正确，但遗漏用户明确要求的换算过程。",
    "suggestion": "补充单位换算过程。",
    "domain": "未定义"
  }
}
```

当前平台没有独立垂域候选列表，按输入适配规则 `domain` 填“未定义”。每产品理由仍使用原固定前缀，缺证写明“暂评”与缺项，依赖保留评测假设时写明“约定判定”。暂评仍保留原Prompt要求的整数评分并进入统计；缺少独立核验状态不清分。只有程序可信采集明确失败，才清除受影响产品的最终分，原模型评分与原理由仍保留供审计。

JSON解析拒绝任何层级重复键、非法数字、字符串/布尔分数、缺项、多余字段、错误产品数量和越界分数，不调用额外模型补造缺失判断。一次评估尝试只有一次语义裁判调用，技术失败仍可使用原平台的手动重跑/恢复能力。

## 存储、展示和统计

模型原对象保存于 `model_product_results`，原字符串保存于 `raw_model_output`；不覆盖平台已有的 `answerN` 复制回答。程序投影为 `answerN_overall_score`、`answerN_overall_reason`、`answerN_suggestion`、`answerN_domain`。胜平负和排名仅按有效整数总分确定，不让模型额外生成相对评价。

支持两/三产品同题交集比较、三产品排序、1—5分布、覆盖率、均分、高分≥4/低分≤2、题图模态分层和多轮会话等权统计。未参与产品不计入分母，技术失败和可信采集失败不伪装0分。两产品互换保持原产品身份，分数、理由、建议、模型观察和图片标签按原身份映射，原始模型响应保持不变；三产品沿用平台原有的身份和互换限制。

前端仅展示综合体验分、每产品原理由/建议/垂域；CSV/Excel、历史详情、运行/重跑审计、数据复用、人工模板导入和人机一致性均使用冻结的同一新协议。人工基准仅新增综合体验维度，不把其他标准的人工分迁移进来。历史缺失或冲突的冻结版本保留原数据并阻断正式续跑与统计，不用当前版本补写历史。

## 验证与部署

新增测试覆盖严格四字段输出、两/三产品输入、字段空值、时间分离、题图/长截图/录屏、多轮目标轮、产品互换、可信失败、历史恢复、统计导出和人机基准。前端通过新增及原有脚本测试。

2026-11-02验证结果：后端 **3132 passed、4 deselected**，全部 **35组前端脚本通过**，FastAPI配置路由验证新标签、唯一综合体验维度与原默认选项。另以基线提交 `8dbb0502` 独立生成13份旧协议指纹，逐一核对每份原请求身份与8种输入组合渲染，均未改变。

排除的4项是既有 `test_stable_plus_service_revision_preserves_inputs_output_and_frozen_history` 参数化哈希断言：基线提交原样运行同样失败，原期望源文件SHA为 `7e2239e…`，当前主分支源文件SHA为 `146379fb…`。此次未修改该旧模板或它的旧哈希期望。完整浏览器视觉验收未完成：本地缺少浏览器运行时，远程浏览器不能访问该本地预览；未将模板编译/脚本检查描述成截图验收。所有模型调用测试使用假客户端，未把功能检查当作实际模型评分效果评测。

更新代码并重启 Web 服务，刷新页面后即可在 compare 的标准选择器中看到新标签。默认选项与其他模板保留原值；已有历史任务继续按其冻结协议运行。
