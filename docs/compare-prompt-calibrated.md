# V0.2 简化版·评分校准（实验）

对比评测新增第三个可选标准，主要校准“有理有据”和“直观高效”的评分口径。原有 V0.2 简化版、V0.3 的 Prompt 保持不变，默认仍为 V0.2 简化版。

## 使用方式

更新代码并重新启动后端后，刷新平台，在新建对比评测任务的评测标准选项中选择 **V0.2 简化版·评分校准（实验）**。选项通过现有 `/api/config` 接口自动下发，无须增加前端硬编码。

API 创建任务时使用：

```json
{
  "mode": "compare",
  "evaluation_profile": "qa_competitor_compare@0.2-simplified-calibrated"
}
```

以上是版本选择字段，任务输入继续沿用原有接口。未指定版本的任务仍使用旧版。已有任务冻结原有协议；要切换版本，应创建新任务。历史恢复和失败补跑继续使用该任务冻结的版本。

| 字段 | 新版本值 |
| --- | --- |
| `evaluation_profile` | `qa_competitor_compare@0.2-simplified-calibrated` |
| `standard_version` | `0.2-simplified-calibrated` |
| `bundle_revision` | `0.2.2` |
| `status` | `experimental` |
| 数值评分 | 1—5 分，沿用 V0.2 输入状态、Gate 和空分规则 |

## Prompt 调整

完整模板位于 `src/auto_eval/judges/visual_compare_prompt_v02_calibrated.py`，是独立版本，不引用或改写既有两个版本的模板。

- **有理有据**：先判断任务是否必须外部来源，再判断主动展示来源触发的评价范围；同题采用共享适用性，但不额外要求无须来源的回答必须提供来源。折叠来源、角标和来源入口本身不直接对应高低分，按来源身份、与正文的关联及任务需求评价。
- **直观高效**：按实际阅读影响评价，不把加粗、标题、图片或表格设为所有回答的必备项，也不因另一产品形式更多而压分。
- **证据边界**：区分可见缺陷与采集不足；录屏结合同一区域后续画面确认最终状态，避免将生成中间态算作最终渲染问题；复制文本不能证明视觉格式缺失；上一轮内容不能归入当前回答。
- **保持结构兼容**：继续使用七维、扁平 JSON 输出和确定性的分维度排名；准确性仍作为诊断信息，不新增加权总分或综合胜负。

新版没有具体测试 Query、实体、专家目标分数或逐题校准示例，保留通用规则与评分分档。JSON 结构示意中的分数使用类型占位符，明确要求实际输出为整数或 `null`。

## 输入组合

| 轴 | 支持值 | Prompt 处理 |
| --- | --- | --- |
| 用户问题 | 纯文本 / 文本与提问图片（VQA） | VQA 沿用共享提问图片说明；提问图片不计入产品回答帧 |
| 回答证据 | 录屏采样帧 / 最终回答长截图 | 按证据模式渲染对应规则；截图按切片定位，不推断时延或流式过程 |
| 产品数量 | 两个 / 三个 | 共用协议，按产品数量渲染字段及证据归属 |

VQA 属于 `compare` 的输入形式，无须新增顶层评测模式。同一条比较仍要求各产品使用同一种回答证据模式。

## 代码接入与统计

- `compare_protocols.py` 注册独立协议，复用 V0.2 结构及分数归一化；旧协议的历史修订兼容规则仍只适用于各自的协议。
- 历史展示与任务恢复共用版本识别逻辑，可从冻结元信息或结果识别新版本。
- 统计按 `standard_version`、`bundle_revision` 和产品数量分别分组；新旧版不混算。校准版的达标阈值为 ≥4、低质阈值为 ≤2，与原 V0.2 数值范围一致，不表示结果可跨版本直接合并。

## 验证边界

自动化测试覆盖版本注册与默认项、API 版本冻结、历史恢复、实际补跑链路、24 种版本/输入/证据/产品数量组合及统计导出。裁判客户端使用替身，不调用真实模型。

本次验证：`python -m pytest -q` 全部 336 项通过；`tests/test_*.cjs` 的 5 个前端测试脚本全部通过；原有两版 Prompt 与接入前提交逐字节相同。

这些检查验证代码兼容性，不能证明人机一致率或泛化效果提升。已有分析样本属于开发与回归材料；新版继续标为实验版，实际效果需要使用未参与校准的新样本验证。
