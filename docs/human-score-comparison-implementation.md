# 人工评分基准对比：使用与实现

2026-09-16，基于 `feat/bailian-request-throughput` 的 `b5076ec` 实施。[原方案](human-score-comparison-design.md)。

## 使用入口

启动更新后的 Web 服务，打开一个已结束的垂域视觉对比任务，在结果区点击 **与人工评分对比**。

1. 选择已有人工基准，或上传 `.xlsx`。也可先选择人工标准，下载当前任务的空白标注模板。
2. 确认人工标准、产品身份、题号列、人工分与 review 列。按物理列地址映射，重复表头不会互相覆盖。高级映射可配置回答来源、适用性和 Gate；已有基准的映射可以复用，表头变化会要求重新核对。
3. 检查解析问题，再保存基准。存在错误时默认拒绝发布；显式选择“仅保存有效记录”后保存排除清单。修改后的文件可以发布为已有基准的新版本。
4. 映射任务中的真实题号和 answer1/2/3 产品身份。可加入其他历史任务、限定题目和维度。不同同分制标准须选择“相对既有人工基准的回归比较”。
5. 生成匹配预览，检查题号匹配、回答身份和旧结果来源。历史信息不足时，可针对当前冻结范围填写确认依据；明确冲突不能确认忽略。
6. 生成报告，查看各任务自身样本或共同有效样本的统计，筛选分歧，导出人机对比 Excel。已保存报告可以重新打开。

人工 Excel 和批注不会进入模型请求。上传、匹配和统计都不调用裁判，也不进入评测请求队列。

## 首版边界

- 支持当前注册的四种协议（V0.2 简化、校准、过程泄露实验版、V0.3）、2/3 产品、文字/VQA、录屏/长截图。
- 仅支持 `.xlsx` 宽表，上传最多 20 MB、数据最多 20,000 行、512 列；最多同时比较 10 个任务。
- 题号按文本精确匹配，保留前导零。数值类型的 Excel 题号需在原表中明确转为文本；不会猜测补零，不使用自动 `q{index}` 跨表匹配。
- review 非空时优先，包括 0 和 N/A。空白是未标注；裸 N/A 默认原因未知。公式只读取缓存，后台不执行公式或外链。
- 内容准确性留档、展示标签覆盖，不计主评分、分位值和排名。不同分制禁止数值报告；未知标准或实现修订只允许匹配预览。
- Gate / 适用性只有双方具有明确可比标签时才统计。人工空白不推断为通过；模型失败不补 0。
- 分位值沿用均分之比，并非百分位数。多任务共同样本按产品维度或产品对求交集，不把不同样本上的一致率差异当作提升。
- 证据按需通过现有授权媒体接口读取；旧链接或文件失效不影响冻结指标。当前媒体内容不自动证明历史输入身份。

## 存储与生命周期

全部位于现有 `RUNS_DIR`，不需要新数据库：

| 目录 | 内容 |
| --- | --- |
| `human_imports` | 上传原始 XLSX、映射和导入预览 |
| `human_baselines/<id>/vN` | 不可变基准版本，案例、人工标签、状态、原表和排除记录 |
| `human_mappings` | 映射档案及表头签名 |
| `human_previews` | 有效期 24 小时的匹配预览和冻结任务 |
| `human_reports/<id>` | 确认记录、冻结输入、指标明细和 Excel |

预览前检查任务终态、`active_runs` 和补跑状态。检查与深拷贝之间不让出事件循环。报告使用该预览的冻结数据，后续更新批或失败补跑不改变旧报告。

报告生成使用独立后台任务，计算与文件 I/O 放在线程中，并发上限 2。重启时把未完成报告标为中断；页面可从原冻结输入重试。正式基准和报告不使用普通 XLSX 下载的短期 TTL，删除原任务也不级联删除报告。预览过期仅限制生成，不自动删除文件；运维清理临时目录时应保留正式基准和报告。

## 代码职责

| 模块 | 职责 |
| --- | --- |
| `human_baselines.py` | Pydantic 导入/标签模型，原子写入，基准版本及映射存取 |
| `human_baseline_import.py` | 安全读表、物理列映射、旧表适配、review/NA/冲突处理、空白模板 |
| `human_compare.py` | 冻结、题号/产品/回答匹配、结果绑定、确认范围、报告生命周期 |
| `human_statistics.py` | 单产品误差、配对产品差距、GSB、共同样本、状态及三产品排名 |
| `human_report_export.py` | 复用现有 OOXML 与 StatisticsTable，输出六张工作表 |
| `human_routes.py` | 独立 HTTP 接口、上传限制、分页及过滤 |
| `static/human-compare.js` | 结果页面板、映射、预览、报告、轮询与取消请求 |

`server.py` 只注册接口和启动/关闭服务。原任务输入、Prompt 和普通评测 Excel 导出保持原逻辑。Web 可选依赖新增 `openpyxl>=3.1,<4`。

接口沿用方案第 9 节，另提供：导入工作表重新读取 `GET /api/human-baselines/imports/{id}`、预览明细分页 `GET /api/human-comparisons/previews/{id}/rows`、冻结报告重试 `POST /api/human-comparisons/{id}/retry`。

## 验证

使用工作区指定解释器 `C:\workspace\venv\Scripts\python.exe`。新增后端测试涵盖四协议 × 两种输入 × 两种证据 × 2/3 产品、152 行旧格式合成表、前导零、review/N/A/公式、重复与冲突、产品换位、结果过期、输入冻结、版本隔离、手算指标及页面/Excel 数据一致。

前端测试 `node tests/test_human_compare_ui.cjs` 覆盖切换报告、取消在途请求、停止轮询、分页乱序和映射修改使预览失效。浏览器使用隔离的合成数据走通选择基准、预览、生成、报告显示流程，未调用真实模型。

验证结果：完整 Python 回归 573 项通过；9 组前端脚本通过。最终补充背景/多轮身份校验后，人工评分相关 54 项后端测试与新面板前端测试再次通过。完整回归需允许本地 ffmpeg 启动，沙箱内曾对两个已有视频测试返回系统权限错误；允许启动后通过。现有 FastAPI `on_event` 弃用警告不影响测试。

原设计引用的业务文件 `人工标注合并结果_20260904_2041.xlsx` 未在当前仓库数据目录中找到；旧表适配已通过同列结构的 152 行合成数据验证，实际业务表仍需首次导入时核对列映射和解析摘要。
