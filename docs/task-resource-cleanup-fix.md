# 任务结束后的资源释放修复

日期：2026-09-10；分支：`feat/long-screenshot-evaluation`。

## 问题与复现

对任务生命周期做静态检查，并用弱引用、垃圾回收、模拟模型及真实测试子进程验证：

| 场景 | 修复前 | 修复后 |
| --- | --- | --- |
| 连续完成 30 个任务，调度器保持空闲 | 最后一个 Task 仍被 worker 的局部变量引用 | 30 个任务对象均可回收，30 个模拟客户端均已关闭 |
| 批量取消 24 个排队任务，等待所有快照保存完成 | 24 个终态任务仍驻留，超过 8 个 LRU 容量 | 24 个任务均退出注册表并可回收；初始任务与失败补跑均覆盖 |
| 长截图或录屏预处理超时 | 协程等待结束，线程仍运行，线程上下文仍引用 Task | 发出停止信号，等待预处理退出后才结束当前任务 |
| ffmpeg/ffprobe 卡在执行或输出管道 | 没有子进程期限；协程超时无法终止它 | 到期或取消时终止该子进程，等待退出并关闭管道、回收监控线程 |

第一项是固定保留最后一个任务，并非每完成一个任务就永久增加一个对象。第二项是异步保存完成后没有再次执行退休检查，批量取消时可以保留超过容量的对象。第三项在底层操作一直不退出时，会持续占用线程、任务引用和子进程资源，重复补跑可能加重占用。

## 实现

- `src/auto_eval/web/scheduler.py`：每个任务结束后清除局部 job/retry 引用；取消排队任务后，在快照保存成功的回调中重新执行退休检查。重新提交的任务仍由 active_runs 和状态保护；保存失败时，本次回调不清除内存任务，以保留恢复机会。
- 新增 `src/auto_eval/preparation.py`：每次预处理有独立的取消信号和总期限，通过线程上下文传递，不修改输入字典、快照或函数的业务参数。超时、取消及重复取消时，调用方均等待后台工作退出，不释放并发槽后留下脱离管理的工作。
- `src/auto_eval/web/runner.py`：长截图、双/三产品录屏、垂域录屏均使用受管理的预处理入口，沿用现有 `video_prepare_timeout_s`，默认 300 秒。
- `src/auto_eval/media.py`：ffprobe、场景检测、采样、单帧提取统一管理子进程。监控线程在取消或到期时终止所拥有的进程，调用方等待退出并关闭管道；场景检测继续流式读取 stderr。处理被中止时直接上抛，不再尝试后续抽帧策略。主要图像分析循环增加停止检查。
- `src/auto_eval/long_screenshot.py`：读取/解码、边界分析、最优切分路径、PNG 编码及写入之间增加停止检查；退出仍执行原有图像关闭逻辑。
- `src/auto_eval/web/video_prepare.py`：产品之间检查停止状态，抽帧被中止后不写 `.complete` 成功缓存标记。
- `tests/test_resource_cleanup.py`：新增 26 个资源生命周期回归用例；`tests/test_web_queue.py` 调整取消后退休的断言时机，等待异步保存完成。

任务内的子进程共用预处理总期限，不会逐个重置超时。如果在预处理范围外直接调用媒体函数，每个子进程默认最多执行 300 秒。

## 验证

在仓库根目录执行（PowerShell）：

```powershell
$env:PYTHONPATH='C:\workspace\auto_eval_agent\src'
& C:\workspace\venv\Scripts\python.exe -m pytest -q -p no:cacheprovider tests/test_resource_cleanup.py tests/test_web_queue.py
& C:\workspace\venv\Scripts\python.exe -m pytest -q -rs -p no:cacheprovider tests
git diff --check
```

- 专项：**33 passed**。
- 全量：**185 passed, 2 skipped, 4 warnings**，约 29 秒。
- 两项跳过均来自 `tests/test_media.py`，原因是本机缺少 ffmpeg/ffprobe；四条警告为已有的 FastAPI `on_event` 弃用提示。
- 子进程测试用工作区 Python 启动真实的阻塞子进程，模拟 ffprobe、流式场景检测、单帧提取和普通命令，覆盖超时及取消。确认进程已经退出、输出管道关闭、监控线程退出，不依赖安装 ffmpeg。
- 图片测试覆盖边界分析、切分路径搜索和 PNG 编码时取消，确认原图对象关闭；视频测试确认中断不生成成功缓存标记。
- 同时覆盖重复取消、取消后立即重新排队、取消时保存失败、正常/异常/取消时客户端关闭，以及连续 30 次导出后无任务对象残留。原有长截图字节、切片、Prompt、双/三产品和历史任务测试继续通过。

## 部署与边界

同步本次 `src/auto_eval` 下的修改及新增的 `preparation.py`，重启服务即可。无需新增依赖、修改配置或迁移历史任务；端口仍为 8054。录屏仍依赖原有 ffmpeg/ffprobe，长截图不因此增加该依赖。评分 JSON、Prompt、原图字节和 Excel 导出格式未改动。

取消采用协作方式，不能强制打断正在执行的单次 Pillow/NumPy 原生操作或文件系统调用。发出停止信号后，任务可能短暂处于清理阶段，直到该操作返回；底层磁盘/原生库永久阻塞仍需要操作系统层面的处理。本次修复消除了已复现的引用残留和脱离管理的预处理，但不是任意故障下的硬实时终止保证。

线程池常驻、当前页面保留结果、历史图片和日志留在磁盘属于既有行为。这里的验证是对象引用和资源生命周期验证，不是线上长期 RSS 压测，也不表示整个进程内存一定立即降回启动值。测试未调用线上百炼服务。
