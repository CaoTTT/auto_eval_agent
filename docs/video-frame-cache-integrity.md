# 录屏采样缓存与证据一致性

## 排查结论

录屏采样有磁盘缓存，位于 `runs/videos/imported/<session>/<case>/`（对比模式再分 `video1/2/3`）。旧实现存在两处可复现的错配来源：

1. 缓存键包含视频路径和部分抽帧参数，但不包含视频内容哈希；`.complete` 只核对算法键和 JPEG 数量。同路径替换视频、或同数量帧被修改后，仍可能读取旧/错误帧。
2. 执行器发现非空 `frames` / `framesN` 就跳过视频准备，补跑和恢复可能绕过缓存校验。

另外，旧目录被不同视频或配置重复抽帧时会覆盖先前的帧文件，影响历史证据引用；历史原视频路径自身也可能已被覆盖。上述是代码及合成数据可复现的问题，不代表已经确认某个具体业务 Case 的原因。

## 修复规则

- 缓存绑定源视频完整 SHA256、路径、长度、算法版本及全部实际 `KeyframeConfig`；不以文件名、大小或修改时间代替内容身份。
- 在原目录下按上述身份生成独立子目录。源视频或配置改变会使用新目录，旧帧路径保留。旧格式缓存不可信，下次需要评测该 Case 时重新抽帧。
- `.complete` 原子发布并记录每帧文件名/哈希及 `keyframes.json` 哈希。文件缺失、字节变化、元数据变化或不完整缓存均重新准备；中途取消/源文件变化不发布完成标记。
- 相同缓存目录的抽取由进程内锁串行保护，等待可取消；通过校验时直接复用帧，不重复运行 FFmpeg。
- 有源视频的执行输入每次进入视频准备检查，包括补跑与暂停恢复。仅含预生成帧、未声明源视频的兼容输入保留既有处理方式。
- 任务保存 `video_source` / `video_sourceN`，含原视频内容指纹，恢复/补跑也保留该信息；Excel 视觉证据清单和帧 ZIP 清单带源视频 SHA256。
- 对已记录指纹的任务，视频预览/原视频下载发现源内容变化时明确报错，不把现在的文件当成历史证据。

## 历史任务处理

不会自动重跑已完成评测或更改已有评分。旧任务在补跑/恢复待执行 Case 时使用新校验；已完成且疑似错配的 Case 需核对源视频后重新评测。若旧视频/帧曾被覆盖，不能只靠当前路径恢复当时内容；应使用原始采集文件。旧记录未保存指纹时无法追溯验证源文件身份。

内容哈希读取会增加少量磁盘 I/O；视频不变且缓存完整时仍省去解码与采样成本。采样算法、JPEG 输出及裁判提示词保持现有行为。

## 验证

覆盖同路径同大小同时间戳替换、帧内容损坏、配置变更、缓存命中、旧标记、并发只抽一次、中途取消/源变化、2/3 产品隔离、执行器重新校验和历史视频下载拒绝错配；另用 FFmpeg 生成红色/蓝色录屏替换同一路径，验证新旧帧内容及历史路径隔离。
