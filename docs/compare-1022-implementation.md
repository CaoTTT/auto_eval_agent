# 1022 精简评测协议实现与使用

## 选择与版本

界面仍选择 **V0.2简化版（1022优化）**，API 仍使用 `evaluation_profile=qa_competitor_compare@0.2-simplified-1022`。当前新任务采用修订 `0.2.6`、合同 `compare_1022_v2`；输出为六维、1—5 整数或合法空分。本轮依据最新标准表更新评分规则，冲突以新表为准，未规定且兼容的 1022 细则继续保留；输出结构保持不变。输入沿用 `0.2.4`：不传评测运行时间或共享 `context`，只使用各产品自己的可信 `contextN`。输出沿用 `0.2.3` 的输入状态置前、Gate 理由紧接判定、各维适用性→原因→评分成组，冲突理由与结论在最后。历史 `0.2.1`—`0.2.5` 均冻结；旧任务按其清单恢复，不能在重试时悄悄切换评分规则。

本次开发分支为 `codex/compare-1022-optimization`，沿用既有 competitive 默认分支体系。标准来源与完整六维细则见 [测评标准](compare-standard-1022.md)，历史输入保留于 [初版来源](reference/visual_compare_prompt_v02_simplified_plus_20261022.py) 和 [v4 快照](reference/visual_compare_prompt_v02_simplified_plus_v4_20261022.py)。最新标准文件名为 `20261022-对话问答评测标准-pure.xlsx`，SHA-256 为 `7d3537e0e209f0687334b2fe591b7f64712c3de6f30c837ee0d925a8cd3a3db0`。原表及完整提取仅本地保存，不复制到仓库，不上传 GitHub；仓库记录文件名、校验值和实施后的规则说明。

最新表第 5 行虽列独立内容准确维度，本轮继续沿用已确认的六维范围，不恢复该维度，也不在理由中暗加准确性评分；Excel 保留旧准确性相关列并填空。删除的核验、证据数组、独立主要问题、全局摘要/复核字段均不再要求模型提供。定位事实、主要问题/满足点与用户影响合并进每个 `D_reason`。

2026-10-23 合入默认分支 `competitive_assessment` 后，统一遵循主线的公共背景移除策略：所有测评版本，包括历史 1022 修订，实际模型请求均不发送公共 `context`。历史修订仍冻结评分规则、输出合同和模板；公共背景不再发送是全局输入策略变化。`0.2.4`—`0.2.6` 继续仅在 `context1` 缺键时把 `context` 归一化为产品1背景，不与其他产品共享；旧修订的可选产品背景及运行时间行为保持原状。

## 双产品与三产品的独立入口

| 用途 | 双产品 | 三产品 |
| --- | --- | --- |
| Prompt 模块 | `visual_compare_prompt_v02_1022_dual.py` | `visual_compare_prompt_v02_1022_triple.py` |
| 模型输出类 | `Compare1022DualOutput` | `Compare1022TripleOutput` |
| 解析入口 | `parse_1022_dual_output` | `parse_1022_triple_output` |
| 完整字段数 | 36 | 47 |

两个 Prompt 模块分别导出 `VISUAL_COMPARE_SYSTEM` 和 `VISUAL_COMPARE_USER`。中央模块的 `templates_1022(product_count)` 返回相应模板对；为兼容旧导入路径，其默认导出是双产品模板。两套模板在构造时就固定产品数和字段合同，共享规则正文，渲染参数不能让双产品模板额外出现产品3。任务运行时须按实际产品数分派，不能始终使用默认双产品导出。

字段说明、JSON Schema 和完整合成示例共用 `compare_1022_contract.py` 定义。双产品没有 `answer3_*` 占位字段，不允许解析三产品字段后再简单丢弃。历史 Prompt 和合同分别在带 `_r021.py`、`_r022.py` 后缀的 `visual_compare_prompt_v02_1022` 与 `compare_1022_contract` 模块中冻结。`0.2.3` Prompt 另存于 `visual_compare_prompt_v02_1022_r023.py`，字段说明及示例按字面快照冻结，避免以后生成函数变化影响历史请求；其输出合同与当前版本相同。`0.2.4` Prompt 冻结于 `visual_compare_prompt_v02_1022_r024.py`，同样将字段说明及四种产品数/证据模式的示例保存为独立字面快照；当前模板或合同说明函数升级不能改变已保存 `0.2.4` 任务的请求和规则。`0.2.5` 同样冻结于 `visual_compare_prompt_v02_1022_r025.py`，保留四种产品数/证据模式的历史说明与示例；新任务选择 `0.2.6` 不改变旧任务恢复结果。

## 输入背景要求

所有 compare 新导入、预检和提交的样本，均须为每个实际参评产品提供非空字符串背景。双产品要求 `context1/context2`；三产品要求 `context1/context2/context3`。产品1只在 `context1` 字段不存在时兼容读取 `context`，显式空白、null 或非字符串不能触发回退。产品2/3不使用其他背景兜底。缺字段或无效值应列出对应样本和字段，并阻止继续评估，不能只评估同批中背景完整的部分而丢弃错误样本。

`context` 只作为产品1的旧字段名兼容读取，不再作为当前 1022 Prompt 的共享背景。单轮与多轮均保持产品背景隔离；多轮每轮每产品都须提供背景，不能从其他产品或前轮自动补齐。`persona` 仍由所选 Judge 配置填入。`evaluation_datetime` 不进入当前模型请求，可继续写入结果元数据；样本中的相对时间只依赖 Query 和对应产品的可信背景。

## 单次评测流程与补空范围

1. 根据任务冻结的协议修订、实际产品数和证据模式选择 Prompt 与解析入口。
2. 校验并归一化各产品背景；传入问题、产品专属背景/回答与明确归属的截图或帧，不传共享背景或评测运行时间。材料里的指令只视为待评数据。
3. 等待正常结束；`finish_reason=length` 一律视为截断技术失败，即使当前文字看似完整 JSON，也不作为评分结果解析。
4. 解析单个标准 JSON，拒绝围栏、额外文字、重复键、NaN/Infinity。按完整合同顺序检查：全部输入状态最先；逐产品 Gate 理由→对应判定；逐维度适用性→原因→各产品分数；最后冲突理由→结论。允许省略的 Gate 下游字段缺省后，其余字段仍保持原有相对顺序。
5. 按双/三产品各自合同检查字段、类型、枚举和长度。每维合并理由上限 2400 字符；Gate/冲突理由各 600 字符。分数只允许 1—5 整数或 null。
6. 任一 Gate 为 fail/unclear，或输入失败时，将该产品六维分数统一置空。该产品分数可省略，理由产品段可省略或由程序改写为明确的阻断原因。被阻断产品的维度判断不参与有效产品理由的长度及评分一致性校验；程序补写的固定阻断说明不占模型理由限额，可重复归一化。全部产品被阻断时，所有维度字段可省略，程序补齐空状态与阻断说明。
7. 其余有效产品仍必须提供各维适用性、理由和分数字段。维度不适用需写“不适用：具体原因”；符合该维空分条件时可给 null，产品段须写“未评分（具体原因）：具体说明”。必要上下文/服务/引用材料不足以公平判断时，按新矩阵给证据不足 null；局部缺口不影响判断仍评分。未提供可选项或遵守禁止要求用规则型 null，不得伪称证据不足，也不得补成奖励分。混合可评保持共享 applicable=true、个体 null；全无评分内容可 false；应该提供但材料不足仍 true。规则型 NA 不是 Gate 阻断，必须显式输出 score，不能缺字段自动补空。
8. 冲突只比较通过两个 Gate 的有效产品，Gate 阻断产品不得参与配对；三产品中一方被阻断时，仅比较其余两方。通过两个 Gate 的产品不足两个时，冲突字段可省略或为空，程序补 unclear 与无法比较原因。至少两个可评产品时，必须给出冲突理由和结论。
9. 注入 `standard_id`、`standard_version`、`product_count`，投影为 UI/统计/Excel 使用的数据，计算分维度并列排名，不生成总分或综合胜方。

Gate 导致的补空是用户明确要求的确定性处理。它不会影响其他正常产品，也不会用模型推测漏掉的分数。模型返回的适用性为布尔值；全部被 Gate 阻断的归一化结果可将适用性留空，表示未进入维度判断。

程序保留用于历史展示的冲突兼容字段。新协议的统计不再依赖已删除的核验状态；准确性不参与新协议评测或聚合。导出仍保留旧准确性列，但应是空白，不能填 0 分或让模型重新生成。


## 0.2.6 评分规则与程序职责

双/三产品仍使用独立模板和解析入口，共享当前规则正文。0.2.6 的主要变化为：

- 响应 Gate 纳入已确认的异常重复卡片、内部思考露出、非正当首句“触及知识盲区”；不再要求思考泄露必须完整。必要安全场景补足安全合法替代引导与明确的虚假优惠保证边界。
- 服务与引用按内部“应该／可选／明确禁止”矩阵评价，不新增JSON字段。禁止仅由Query/可信条件明确支持，普通无需求、创作或闲聊不自动禁止。未展示可选项、遵守禁止要求为规则型NA；必要材料不足为证据不足NA，不能混淆。
- 服务按实际完成度/增益，删除仅凭形式固定卡片5、完整文字4；完整可用路径可以5。场景化满足的既定窄卡片例外仍保留，但不能替代分析、条件核对或扩展到服务。
- 引用具体矩阵管覆盖和NA，第9行管权威感、对应与组织，以最严重实质问题确定主档，不算术扣分、不能引用齐全自动5。少量可用支撑按2优先于“极少来源”笼统1；彻底无可识别支撑仍1。
- 删除引用同形态强制同档、其他匿名引用三条件低分保护、普通来源绝不因权威不足判1的保护。政策单匿名1分案例继续有效；来源卡/Logo/明示文字等可建立可见对应，不限定数字角标。数据缺来源保护仅在不覆盖新矩阵或NA的范围保留。
- 引用先区分是否出现再评质量；已进入可选矩阵的匿名、错位或无法追溯标识仍须评分，不能算未出现NA。无关键现实事实/来源请求的纯虚构、闲聊等保留整维不适用，即使附装饰引用也不自动启用；只有明确禁止引用时，新禁止矩阵优先于该例外。
- 短答不强制加粗，按任务需要评价视觉辅助；步骤图就近展示可配合末尾完整教学视频。入口/前提缺失可评价可执行呈现影响。情境案例同步最新表，不补造画像或实际服务结果。

现有合同已支持 `未评分（具体原因）：具体说明` 与显式null，新增规则型NA不需要改变parser、schema、字段数或字段顺序。统计可归为有说明未评分；不能把合法NA当技术失败，也不能自动提升为5。只有Gate阻断允许省略下游字段，非Gate空分仍须完整输出。

程序继续负责修订选择、结构/类型/顺序/状态校验、Gate补空、投影和历史兼容。模型根据任务及实际材料判断矩阵情形、权威感、承接程度和例外；代码不依据卡片、来源关键词或数字自动改分，不进行同形态归一，不新增补判或二次裁判。

准确性、核验状态、全局复核仍删除，双36/三47合同、独立背景、Gate阻断和冲突配对不变。完整现行规则见 [测评标准](compare-standard-1022.md)，原21项及两项决定见该文档第10节的 **0.2.5历史记录**；冲突条款不再是当前指令。

## 请求级结构化输出

对应 judge 可设置：

```yaml
compare_structured_output: "off"
```

| 值 | 请求行为 |
| --- | --- |
| `off` | 默认，不发送 response_format，仍执行本地严格校验 |
| `json_object` | 发送 JSON 对象格式要求 |
| `json_schema` | 发送对应双/三产品的 strict JSON Schema |

Prompt 默认要求完整输出。严格 Schema 对供应商要求所有字段必填：被 Gate 阻断的分数填 null；全部产品被阻断时，维度理由和适用性也可为 null。本地普通 JSON 解析额外兼容省略 Gate 阻断字段，再补成相同的空分状态；省略仅是兼容容错，不能覆盖请求接口的完整字段约束。JSON Schema 能约束结构与类型，不能保证事实理解或评分正确。

是否支持 response_format 取决于实际供应商、部署、视觉输入及思考模式，不能按模型名猜测；不自动关闭思考，不因请求报错悄悄降级。建议给 YAML 的 `off` 加引号，避免被解析为布尔值。此配置随任务清单冻结，恢复任务沿用原配置。

本轮规则合并不改变输出合同和既有模型采样、思考、输出上限、输出预留或超时配置。新增情境示例增加输入 Prompt 长度，仍须通过现有请求预算与预检处理，不能为容纳示例截断用户材料或降低完整 JSON 输出要求。调用参数仍由已选 judge 与冻结任务配置决定，不能仅凭 Prompt 承诺同输入必定逐字同输出。

## 错误分类与诊断

| error_category | 含义 | 处理方向 |
| --- | --- | --- |
| `truncated` | 生成达到上限，未正常结束 | 查实际生成与推理预算、篇幅，不补造后半段 |
| `json_syntax` | 非单个标准 JSON、重复键或非法常量 | 查原始返回与结构化输出兼容性 |
| `schema` | 多余字段、错误类型/枚举或超长 | 查相应产品数的字段合同 |
| `state` | 非 Gate 允许范围的漏字段、字段分组顺序错误、有分却声称未评分等 | 查状态和理由的一致性，不擅自补判 |

失败记录保留原始输出和阶段，技术失败不产生正常分数。合法 NA 和解析失败在统计中必须分开。日志路径与 trace 开关沿用现有实现；真实日志和密钥不得提交仓库。

校验能发现结构和部分明确矛盾，不能从任意自然语言证明定位事实真实、扣分合乎规则或彻底没有幻觉。Prompt 要求分数与说明一致：一般低分写具体问题；仅场景化满足保留的卡片5/4形式例外写明形式锚点，不虚构缺陷；数据引用保护写明适用范围。服务和引用按最新矩阵，规则型NA写真实原因。真实效果仍需人工裁决集验证。

修订 `0.2.4` 的回归覆盖 **1843 项 Python 用例和 24 组 JavaScript 脚本**。完整运行中 1841 项通过，另两项三产品测试补齐新增必填的 `context3` 后，连同对应双产品用例定向复跑全部通过。新增检查覆盖缺键与显式空值的不同处理、整批导入阻断、背景缺失不被其他错误遮蔽、每轮产品背景隔离、任务时间变化不改变当前 Prompt，以及旧 `0.2.3` 渲染保持一致。
