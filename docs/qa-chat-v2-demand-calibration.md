# 闲聊V2需求与分档校准候选

平台新增 **问答闲聊V2·需求与分档校准·1-5分（候选）**，用于减少把分享当求方案、把简单完整回答当单薄，以及理由与分档脱节的问题。原“问答闲聊V2·1-5分（候选）”和默认标准保持原样。

## 本次调整

仅调整理解需求、情感表达恰当、风格恰当、场景化满足、引导推荐五维的执行说明：

1. 先判断当前主要目的、明确要求和有依据的隐含需求，再选择相关评价子项。分享、倾诉不必额外提供方案；求方法或话术不机械要求先安慰。必要澄清不直接视为回应不足。回答实际引入的缺陷仍须评价。
2. 五维逐产品核对证据、实际表现及影响与原档位。3/4分说明具体不足及影响，5分说明相关高分要求如何满足。不因简短或常见表达自动降分，不因没有指出缺点自动满分，不增加默认分、固定扣分或分数上限。

原标准全文与案例直接复用原模块，原输入USER模板、输出示例和Schema也复用原实现。个性化适配、Gate、维度适用性、核验及空分规则不调整。

## 证据核对补强（修订1.1.2）

基于新一批216题的审核，候选已覆盖需求识别和相关子项分档，本次优先补强评分前的证据核对，不再增加单题案例或新的评分条件：

1. 声称“未回应、缺少、未提供”前，完整核对目标轮图文及语义等价内容；区分确实缺失、已有但不足和材料无法确认。复制文本冲突继续按原视觉证据优先级处理。
2. 保留主语、否定、条件、确定程度及先后顺序，区分祝愿、希望、可能性与事实断言；条件词也不是免责条件。检查整段正负证据，不由一句正确提醒抹去其他矛盾。
3. 分开采集时刻、评测运行时刻和用户明确的事件时间。时间位置不能独立推出生日、经历或活动；产品自述不独立证明历史真实，来源不清也不单独证明编造，仅限制依赖该来源的维度。
4. 按各产品自身证据先绝对评分，再比较结果。另一产品多给的分析、选项或新颖措辞，不自动成为本产品的缺陷；跨维评价需要独立影响。

平台仍使用同一候选标签、协议ID、标准版本和结果Schema，输入USER模板及双/三产品56/78键保持不变。原标准全文、Gate、适用性、核验、空分与个性化规则未改。

新建该候选任务使用1.1.2。修订1.1.1的原模板冻结于 `visual_compare_prompt_qa_chat_v2_calibrated_r111.py`，历史任务恢复与补跑继续绑定原模板，避免同一任务混用两版Prompt。标准边界和证据不足的案例仍需统一口径或补证，本次不替其发明确定答案。
