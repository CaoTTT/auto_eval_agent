# 时效性评估：内容冲突检测补充标准

适用协议：`timeliness_compare@1.0`，当前包修订 `1.0.2`，结果合同 `timeliness-result-3`。更新时间：2026-10-20。本项在原有两个Gate、理解需求/权威性/时效性三个1–3分维度之外，增加一个整组分类结果；仍然一次输入、一次模型评审、一次扁平JSON输出。

本补充来自仓库V0.2标准及本次迁移约束，不属于《时效性监控-测评标准》专家修订版v1.0工作簿原文。[原表快照](timeliness-standard-v1.0.md)的单元格正文和SHA-256保持原样，不将新增规则标成原表条款。原表三个评分维度及阻断规则不变。

## 1. 来源与有效版本

当前注册的来源是 `qa_competitor_compare@0.2-simplified-plus`，包修订 `0.2.2`，界面名“V0.2 简化版（稳定plus）·1-5分”。注册和模板导入见 [compare_protocols.py](../src/auto_eval/judges/compare_protocols.py)，实际模板为 [visual_compare_prompt_v02_simplified_plus.py](../src/auto_eval/judges/visual_compare_prompt_v02_simplified_plus.py)。

该模板最近的更新提交为 `bf24a1f`（2026-10-16）；“十九、内容冲突”段来自 `bef389d`（2026-10-15），后续修改未改变此段定义。现行v0.2简化版、评分校准和思考暴露优化模板采用同一核心口径。思考暴露模板的`0.2.4`仅供历史任务冻结，不能仅按文件名或更高修订号将它当作当前可选标准。

以下完整保留来源模板中的内容冲突定义；其中`content_conflict`是V0.2模型原始字段名。原有V0.2解析时将其映射为平台结果字段`has_conflict`。本次时效性严格合同直接使用`has_conflict`，不同时输出两个别名。

## 2. V0.2内容冲突定义原文

内容冲突只检查用户核心关注的事实性命题，不比较篇幅、覆盖范围、主观偏好、推荐选择或表达风格。

- content_conflict=yes：至少两个产品针对用户核心关注的同一事实对象、同一事实属性，并在相同时间、地区、版本和适用条件下给出相互排斥的事实、数据或状态。例如同一城市同一天最高温分别为28℃和32℃；同一商品同一规格同一时间价格分别被明确写成两个不同数值。
- content_conflict=no：产品事实说法一致或可以同时成立；只是信息互补、详略不同、一方遗漏某事实；一个产品回答事实A、另一个回答不同事实B而没有共同可比较命题；或者只是主观审美、推荐方案和价值判断不同。一个产品提到A、另一个没有提到A，不构成冲突。
- content_conflict=unclear：产品看似谈论同一事实，但截图模糊、对象指代不清，或时间、地区、规格、版本、口径等条件不足，无法判断两种说法是否在同一条件下互相排斥。不得仅因两个产品覆盖内容不同而输出unclear。

判断步骤：

1. 先提取用户核心关注的事实命题；
2. 检查至少两个产品是否都对该同一命题作出事实性陈述；
3. 对齐对象、属性、时间、地区、规格、版本和口径；
4. 只有对齐后仍然互相排斥，才输出yes；
5. 三产品模式中任意一对满足上述条件即输出yes，并在conflict_reason中写明冲突产品和命题。

冲突只说明产品说法不一致，不判断哪一个正确。不得使用多数投票认定事实真伪。

## 3. 来源模板的相关证据与复核要求

V0.2“时间、上下文与证据边界”同时要求：回答文本和关键帧只能证明产品展示、表达或声称了什么，不能自动证明外部事实真实；天气、价格、新闻、赛事、库存、营业时间、政策、优惠、产品版本等强时效事实没有可信参考材料时，不得凭训练记忆猜测。没有覆盖某部分只能表示证据不足，只有画面明确出现相反内容才能判定文本与画面冲突。

产品专属背景只能用于对应产品。内容冲突只比较同一对象、属性、时间和适用条件下的同一核心事实，不以多数产品的说法认定少数产品错误。时间处理迁移时仍遵循时效性原表：采用材料中的实际测试条件和用户目标时间，不将当前审核日期替换成测试时间。

V0.2要求`conflict_reason`使用简体中文，给出冲突或无冲突摘要；三产品必须写明冲突产品和命题。其通用证据要求是描述可观察事实、标明产品和文本/帧位置，不捏造帧号、链接内容或点击结果。原输出含全局`evidence`，没有独立的冲突证据数组。

V0.2的confidence分为high（关键输入完整、直接证据充分、分值边界清楚）、medium（部分缺口或边界判断但不影响主要结论）、low（输入不完整、关键组件模糊、适用性或分值高度不确定）。它没有规定发生冲突就自动降低confidence。原Prompt将“存在重大产品冲突且无法判断”列入人工复核条件，也未规定所有yes都自动复核。本次保持精简模型合同，不增加confidence字段；为使不确定检测可被平台明确跟进，程序统一将`has_conflict=unclear`列入待复核。

原有数值评分、Gate和排名不由内容冲突字段直接控制。该边界继续适用本次迁移：yes是“存在互斥说法”，不是“所有产品都错”或某方自动扣分；no不是事实正确或版本最新的证明。

## 4. 当前时效性协议中的执行规则

### 4.1 核心命题与三态

仅比较用户核心关注的事实命题。先确认至少两个产品都作出陈述，再对齐对象、属性、时间、地区、规格、版本、口径和适用条件。天气数值须对齐地点、日期和统计口径；价格须对齐商品、规格、时间和优惠口径，不能只看到数字不同就判yes。

- **yes（有冲突）**：至少一对产品在条件对齐后仍给出互斥事实、数据或状态。理由指出具体产品对及冲突命题。
- **no（无冲突）**：可见说法一致或能共存，或仅为信息互补、详略、单方遗漏、不同事实、主观审美/推荐/价值判断差异。理由说明实际属于哪种情形。
- **unclear（不确定）**：看似同一事实却无法确认可比条件，或关键回答缺失/不可读，以致无法判断是否存在冲突。理由写明缺少的对象、时间、版本、口径或具体内容；不能泛写“无法判断”。

完整可读的拒绝或限制说明不是输入缺失。不能仅因两产品覆盖内容不同而unclear，也不能将无法观察的关键回答当作no。若不足两份核心回答可判读，且无法排除冲突，应unclear。

### 4.2 三产品与前置阻断

三产品逐对检查。任意一对已有充分证据构成冲突，整组即yes；其他对的条件未知、内容不可读不抵消已证实的冲突。没有已证实冲突而仍有影响判断的可比性或内容缺口时，整组unclear。理由不得把一对冲突归责全部产品或全部产品对。

响应/安全Gate fail、理解1分只阻断该产品原有数值评分，不抹掉其清晰可读的事实陈述。可比事实仍按本补充标准独立判断；阻断不自动使整组no，也不能用不清晰的片段强行凑出yes。

### 4.3 时间与版本

先区分产品陈述声称适用的时间与其引用材料的发布时间、数据年份。明确分属不同时间、规格或版本且能同时成立时为no；无法确认是否同一条件时为unclear。若双方都声称适用于同一用户目标时点，不能仅凭所引用年份不同就免于比较。

实际测试时差可能解释动态变化且无法排除时，不能据此判yes。明确不同时间且陈述可共存，与无法确定时间是否一致是两种不同情况，应分别说明。

时效性扣分仍须独立满足原标准R07、R13、R14等关于版本替代、适用条件和核心影响的要求。内容冲突yes不直接推出权威性或时效性1分；已证实某信息采用旧版本，也未必和另一产品对不同时间的陈述冲突。两项判断可以不同，各自保留证据。

### 4.4 多轮与产品内部不一致

只检测目标轮仍陈述、明确沿用或依赖且影响当前回答的核心命题。历史仅用于解释各产品自己的指代、条件和纠正，不能借用另一产品历史补全本产品；不读取未来轮，不重复处罚已经纠正的历史差异。

产品自身正文与截图不一致、同一产品前后自相矛盾，不自动等于产品间冲突。只有至少两个产品的当前核心事实陈述符合本补充的互斥条件时，才输出yes。内部时间矛盾仍可按原时效性条款独立作为证据。

## 5. 输出合同与理由

在三个评分维度之后，按以下次序输出两个必需字段：

```json
{
  "conflict_reason": "产品1与产品2在目标轮均回答同园区、同日普通游客的开园时间。产品1图1正文为“今天09:00开园”，产品2图1正文为“今天08:00开园”；测试条件和目标日期一致，两个最早入园时间互斥。此结论不单独裁定哪一方正确。",
  "has_conflict": "yes"
}
```

上例只展示新增字段和理由格式，不是完整模型结果，也不代表真实产品测评。

`conflict_reason`必须是非空中文字符串，包含具体产品对、核心命题、关键对齐条件、双方短原话或具体可见事实及产品/目标轮/图块或区域位置，并解释为什么互斥、共存或无法判断。不可读时如实说明缺口，不为满足格式捏造第二份引文。只写“有冲突”“一致”“无法判断”等泛泛结论不足以审计。

`has_conflict`只能是字符串`yes`、`no`或`unclear`，不允许NA、null、布尔或1–3分。模型不再输出`content_conflict`别名，不增加冲突证据数组、逐对结果对象、置信度、总分或第二次模型调用。

当前基础键数为`4N + 3×(N+2) + 2 = 7N+8`，两产品22键、三产品29键；权威性/时效性条件NA分类仍最多增加2N键，因此总数分别22–26、29–35。JSON按键名解析，固定理由在前的顺序用于输出组织和审计，不把顺序变化当作语义分数变化。

历史`1.0.0 / timeliness-result-1`与`1.0.1 / timeliness-result-2`按原Prompt/Schema读取和续跑，没有本检测结果时显示“未采集（旧协议）”，不补成no，也不使用新规则倒填历史结论。要使用新检测创建采用当前修订的任务。

## 6. 展示、统计与复核

页面和导出在整组层级展示冲突结论及理由，不给每个产品新增冲突分。unclear由程序列入人工复核，不自动清空原评分；yes本身不触发自动改分或裁定哪方真实。

模型原始判断与程序的统计资格分开保存。当前协议中，只要任一活动产品的可信采集状态`input_status=failed`，程序就将整组的展示/统计状态标为`input_failed`（“采集失败，待核验”）。两产品和三产品采用相同的保守处理：保留模型原始`has_conflict`和`conflict_reason`供核查，但不把该组计为已确认yes/no，也不加入明确冲突率的分母。

这一处理不修改第4节的模型判断规则。三产品中，模型仍可能根据另外两份充分材料正确输出yes；程序没有独立结构化的冲突产品对，不能可靠地从自由文本理由提取归属并自动确认该yes完全不依赖失败材料，因此暂不将整组纳入已确认统计。程序不会把原始yes覆盖成unclear或no，也不会因这一统计资格状态改变原有三个维度的评分。Gate fail或理解1与可信采集失败不同，前者本身不触发`input_failed`。

统计单列yes、no、unclear、采集失败待核验和未采集数量。明确冲突率为符合统计资格的`yes/(yes+no)`，分母为0记NA；unclear、`input_failed`和旧版本未采集不计入该分母，不将它们当no。旧协议没有本检测时继续显示“未采集（旧协议）”，不由该派生规则补造检测结果。该整组统计不归责某产品或每个产品对，不改变三维有效分数、覆盖率及共同可评分交集的口径。

## 7. 构造边界案例

这些案例用于规则校准，不是外部事实答案，也不预设未提到维度的分数。程序合同测试只能验证结构、复核及兼容行为，模型语义判断仍需使用标注截图验证。

| 案例 | 材料与条件 | 冲突结论及边界 |
| --- | --- | --- |
| CF01 同条件温度 | 两产品均明确回答同城市同日同口径最高温，一方28℃、另一方32℃ | yes；记录双方原话及位置，不裁定真实温度 |
| CF02 信息互补 | 一方介绍营业时间，另一方补充交通方式，没有相反的共同命题 | no；覆盖不同不应unclear |
| CF03 单方遗漏 | 一方说某景点周一闭馆，另一方没有提及闭馆时间 | no；没有陈述不等于否定 |
| CF04 主观推荐 | 一方推荐A、一方推荐B，理由为个人偏好，未包含同条件互斥事实 | no；选择不同不构成事实冲突 |
| CF05 条件未知 | 同商品出现两个价格，但规格、优惠条件或时间没有交代清楚 | unclear；列明具体不可对齐条件，进入复核 |
| CF06 明确不同时间 | 一方明确陈述9月价格，另一方明确陈述10月价格，均没有声称是同一天价格 | no；不同时间可以共存；版本是否适用于query另评 |
| CF07 同目标不同引用年份 | 双方都回答同日现行开放时间，但援引不同年份，给出不同结果 | 不能仅按引用年份免除比较；适用条件可对齐且互斥则yes，否则unclear；时效性另举证 |
| CF08 三产品一对已证实 | 产品1和2满足CF01，产品3图像缺损 | yes；第三方缺证不抵消1与2的冲突，也不能归责产品3 |
| CF09 三产品未能排除 | 产品1和2一致，产品3核心回答不可读，且无已证实冲突 | unclear；不能据两份一致结论替第三份填no |
| CF10 评分阻断 | 某产品理解1或安全Gate fail，但核心事实片段清晰可读且与另产品同条件互斥 | yes；原评分继续按阻断规则处理，不恢复分数 |
| CF11 历史已纠正 | 产品前轮不同，本轮已明确修正为一致答案 | no；不重罚已经纠正的历史差异 |
| CF12 历史继续沿用 | 本轮明确沿用本产品前轮事实且影响当前结论，与另一产品当前同条件事实互斥 | yes；在理由同时定位目标轮沿用及本产品历史依据 |
| CF13 拒绝与回答 | 一方完整可读地说明无法确认实时结果，另一方给出事实；没有相反陈述 | no；完整限制说明不是输入缺失，不证明另一方正确 |
| CF14 双方关键内容缺失 | 仅一份或没有可读核心回答，无法判断是否有相反陈述 | unclear；不能把采集未知当无冲突 |
| CF15 内部不一致 | 单一产品文字与截图矛盾，另一产品未对同一命题作出陈述 | 不因此直接yes；本题产品间无互斥命题且其余材料可判时no，若关键内容归属无法确认则unclear |
| CF16 时效性与冲突分离 | 一方明确讲旧年规则，另一方明确讲新年规则，存在可见版本替代证据 | 两说法可共存则no；旧规则是否错误用于目标时点仍按时效标准独立判分 |

运行Prompt见 [visual_compare_prompt_timeliness.py](../src/auto_eval/judges/visual_compare_prompt_timeliness.py)；完整可复制版本见[最终完整Prompt](timeliness-evaluation-prompt-final.md)，接入和输出说明见[设计文档](timeliness-evaluation-design.md)与[输出合同](timeliness-evaluation-prompts.md)。
